## 0. 一句话结论

**能力面已经过剩，缺的是「可证明」「可运维」，以及「被看见」。**

内部三条硬事实：
① **43 条契约全是正样本**，测不出越权/过期/已取代——这是「可证明」的核心缺口；
② **4 个「文档说做了、代码只做一半」的缺口**（降级对模型不可见、save 无幂等键、跨实例准入闸失效、同 query 不幂等）；
③ **使用高度集中在一个人**（成员A 占注入尝试 59.7%），所以「注入率 42.9%」这类结论目前只代表 1~3 人。

外部三条判断（相对第三轮要改口）：
① 没有出现能动摇「ES + 一人一索引 + 中文」路线的对手，**记忆仍未进入 MCP 协议层**（SEP 45 份里 0 份 memory），被标准化的是 Skills；
② 但**中文已失守一半**（22 条 memory 明确做 CJK，@restregular 月下载 20,048 就是 BGE-M3 + 面板），**治理/面板已成标配**（94/473 有面板）；
③ **我们不在市场**——`dsh-memory-es` 在 npm 404、官方目录 10,974 条里 0 命中。这是分发问题，不是能力问题，但决定了有没有人用。

真正值得抄的只有三件新东西：**注入层硬预算**（Claude Code 200 行/25KB，超限写入成功但回错误要求重排）、
**失效靠撤销不靠覆盖**（`valid_until`/`revoked_by`）、**自动召回的噪声是多重检验问题**（阈值随 N 漂移，
这解释了「继续」那 336 轮为什么每次灌 3 条无关记忆）。

**自建 vs 托管（诚实版）**

| 维度 | 我们 | 托管 |
|---|---|---|
| 中文检索 | ✅ ik 词典 / 字段权重 / RRF / 时间衰减都能改 | ❌ 只给 Rerank 开关与 metadata 过滤，不暴露分析器 |
| ACL | ✅ 落在存储层（一人一索引 + 索引级 ACL） | ⚠️ 靠调用方传 scope/namespace，传错即跨用户 |
| 审计与边际成本 | ✅ 全在内网，50 人规模检索近免费 | ⚠️ 按量计费，且数据出网 |
| 自动抽取/合并/冲突消解 | ❌ 手工作坊（蒸馏 + 规则） | ✅ 产品化（AWS 5 策略含 episodic 反思、Azure LLM 合并去重、阿里画像+技能记忆） |

**结论（要认）**：选自建的理由只能是**中文 / ACL / 内网**，不能是省钱。
托管真正更强的是「自动抽取质量 + 免运维 + 合规资质」，这三条短期补不上，应在定位上说清楚，而不是硬比。

## 3. 评测口径变了：一个「答对率」拆成四件事

第三轮之前大家比的是「答对率」；近三个月（2026-08 之后）的共识是拆成四项分开算，
这对我们的「43 条契约」是一次直接的方法论升级。

| 维度 | 新口径 | 对我们的含义 |
|---|---|---|
| 召回 | R@5 / MRR，**不调 LLM** | LongMemEval-V1（cleaned）的 evidence turn 带 `has_answer`、每题有 `answer_session_ids`，可直接算；自带 `flat-bm25` 基线可对拍 |
| 该不该进上下文 | 注入精度 / 弃答率 | 我们的 `low_confidence` 652 条是这一维的原材料，但目前只当护栏、没当指标 |
| 写入与失效 | 待定计划被写成现状的比例 | AgentMemGate 实测未加门时 Mem0 35.2% / Graphiti 27.3% 的待定计划被写成现状；我们靠 quarantine，只挡凭据与再摄取，不挡「计划当事实」 |
| 成本 | token / 毫秒 / 注入条数 | Claude Code 的注入层硬预算是现成范式（见 §5） |

**近三个月最值得借的三个机制**（均带链接，见 `r4-eval-academic.md`）：

1. **写入准入门放在抽取之前**（Gated Memory，arXiv:2610.11270）：用完整原句判「永久属性 vs 临时情境」。
2. **失效靠撤销，不靠覆盖**（TEPA，arXiv:2608.07429）：加 `valid_until`/`revoked_by` 即可起步；
   全反转场景 0.950 vs append-only 0.210。我们 `supersede` 只有状态，没有「当时为什么失效」。
3. **主动召回是多重检验问题**（Price of Scale，arXiv:2610.34507）：N=8 调出的 5% 误报阈值，
   到 N=2048 变 84~100% —— 这正是「继续」那 336 轮每次灌 3 条无关记忆的根因，不是排序不够好。

**评测进 CI 的结论**：不用 LLM 裁判也能做。零成本四件：
给 43 条契约加负样本断言（跨用户/已 supersede/过期/非 pinned，断言 top-k **不含**）；
冻结时钟 + RRF tie-break 按 `doc_id`（否则时间类断言天天红）；
建 200~300 条中文脱敏 gold-set，门禁只看相对基线（BM25-only vs BM25+kNN+RRF 的 R@5 不得为负）；
索引快照化（pin mapping + ik 词典 + bge-m3 版本）。
裁判只做趋势：换模型能让宽松度动 56.1 个百分点，**不进 CI 门禁**。

## 6. 明确不做（复述防跑偏）

| 做法 | 理由 |
|---|---|
| 换存储后端 / 引图数据库 | 一人一索引 ACL 建在 ES 上；第三份数据源=新故障类 |
| 替换 mnemon | 已铺满 12/12 停用（34），不再并存 |
| 检索单位上移（阶段 26） | 库 632 条 < 准入线 2000，无证据支撑 |
| 蒸馏批处理 | `distill_state` 无 pending 积压，优化空转路径无收益 |
| 跨库建边 | 用户 2026-11-02 定案；会让「两库各一份」看起来像一条 |
| 自动 supersede | 谁被推翻只能由写入者说明，系统不替人猜 |
| 闲聊记忆单独分类 | 2026-11-05 已否掉（库存里没有闲聊记忆） |
| LLM 每轮自动复盘 / 用 LLM 裁判进 CI | 成本与方差都不划算；裁判只做趋势 |
