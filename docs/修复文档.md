- [ ] **1. 注入超时 100% 被记成 error，且落盘无原因**（审查 H1）
  - 位置：`src/recall-inject.ts:313`（`classifyInjectError`）、`src/es/http.ts:121`（`EsError` 的 `this.name='EsError'`）、`src/es/http.ts:337-349`（abort 被包成 `EsError{kind:'aborted'}`）、`src/index.ts:1036-1045`（catch 落盘无 `note`）。
  - 问题：注入靠 `AbortSignal.timeout(500)`，abort 经 ES 层包装后 `name='EsError'`，而 `classifyInjectError` 只认 `TimeoutError`/`AbortError` → **恒返回 `'error'`，`'timeout'` 分支在生产不可达**。已实测：8 条 error 的 ms 全贴 500ms（501/501/502/506/507/516/517/752）。影子侧没这 bug（用 `Promise.race` + `TIMEOUT` symbol，不看 `name`，且带 `note`）。
  - 修法：① `classifyInjectError` 改为 `err instanceof EsError ? (kind==='timeout'||kind==='aborted' ? 'timeout' : 'error')`，再沿 `cause` 链遍历兜底（`es/http.ts` 不 import `recall-inject`，**无循环依赖**）；② `InjectRecord` 加 `note?: string`，catch 里写 `String(err.message).slice(0,120)` 并带上 `err.kind`（对齐 `recall-shadow.ts:235`）；③ 给注入的 `searchMemories` 传 `log`（`index.ts:968-987` 现在不传，`search.ts:484` 算好的 `formatEsError` 被 noop 白扔）。
  - 验收：`tests/recall-inject.test.ts` 补 **`EsError` 实例**用例（现有 `:96-105` 只用合成 `name`，永远抓不到）；跑一段后 `recall-inject.jsonl` 里出现 `outcome=timeout` 且 error 记录带 `note`。
