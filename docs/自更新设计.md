# 插件自更新设计（v2）

> 状态：待评审。2026-11-11 修订。
> 目标：插件自己每天 06:00 检查新版本，有新版则自动完成「迁移前置 → 安装 → 延迟重启」，
> 设置页可一键关闭，默认开启。
>
> **v2 修正**：ES 是共享的（`dsh-xqh` / `dsh-test` / `dsh-liuxinling` 实测全部指向
> `https://dsh-es:9200`），索引迁移是**管理员侧的一次动作**，成员容器只换代码。
> v1 里「每个成员各自迁移 + 给每个账号加 manage」是错的，已删除。

## 1. 需求（用户已确认）

| 项 | 结论 |
|---|---|
| 检查时间 | 每天 **06:00**（成员实例）；管理员实例提前到 **05:30**（保证先迁移后升级） |
| 来源 | GitHub Release：`xqh0405/dsh-memory-es`（现有 `release.yml` 会传 `tar.gz` + `.sha256`） |
| 迁移 | **只在管理员实例执行**；成员只做只读体检 |
| 生效 | 安装成功后**延迟 60 秒**退出，由 systemd / 容器 restart policy 拉起 |
| 开关 | 设置里 `update.enabled`，默认 `true`，可关 |
| LLM | 只在管理员侧迁移失败时被叫一次做诊断，**不执行任何命令** |

## 2. 已实测的事实（不是假设）

- 125 容器内：`dsh` CLI、node v24、`tar`、`curl` 齐全；`api.github.com` 与 release 下载均 200（0.27~1.32s）。
- 本机 `dsh-web`：`Restart=always`、`RestartUSec=5s`。
- 125 全部 11 个 `dsh-*` 容器：`restart policy = unless-stopped`。
  → **更新后不需要 docker / systemctl 权限**：进程退出即被拉起，本机与容器同一套机制。
- **11 个容器共用同一套 ES**（`https://dsh-es:9200`），每个实例用自己的 `mem-user-<uid>` 身份，
  只读写自己的 `personal_memory_<uid>` 等索引；索引模板是全局的。
- 运行时账号没有改映射的权限：`mem_personal_rw_<uid>` 只有 `read/index/delete/view_index_metadata`。
  → 所以**成员不迁移**，只做只读体检（读 `_mapping` 用 `view_index_metadata` 就够）。

## 3. 迁移与升级的分工

ES 是共享的，因此两件事必须分开看：

| 动作 | 谁做 | 频率 |
|---|---|---|
| **索引迁移**（模板 + 各索引 `_mapping` 补字段） | 管理员实例（`update.migrate = true`）或人工脚本 | 每个需要加字段的版本一次，全体共享 |
| **代码升级**（替换 `lib/` + `panel/`，退出重启） | 每个实例自己 | 每个版本每个实例一次 |

**成员的只读体检**（升级前置条件）：拿新包 `scripts/init-indices.sh` 的模板字段，比自己索引的
`_mapping`。缺字段 → **跳过本次升级**，面板提示「索引未就绪，等管理员迁移」。不装、不重启。
这样即使管理员漏迁，成员也不会写 400，只是晚一天升级。

**管理员自动迁移**（`update.migrate = true` 时）：从新包模板提取 `properties`，与当前
`personal_memory_<uid>` / `personal_doc_<uid>` / `search_log_<uid>` / `personal_audit_<uid>`
的 `_mapping` 比对，只补缺失字段（`PUT _mapping`，幂等）。三类情况拒绝自动迁移：
类型变化、字段被删、团队库（`team_knowledge` / `memory_audit`）变更 —— 面板给差异，人工处理。

## 4. 模块与数据流

```
src/update.ts（新）
  compareVersions(a, b)            纯函数：三段比较，只升不降
  isDue(at, tz, lastCheckedDate)   纯函数：今天 06:00 过点且今天没检查过
  parseTemplates(initIndicesText)  纯函数：从 shell 文本提取模板 JSON（按模板名匹配）
  diffMapping(templateProps, currentProps)
                                   纯函数：{ additions, typeChanges, removed }
  planUpdate({ localVersion, releaseVersion, mode, diff })
                                   纯函数：skip / wait-index / install / migrate-then-install
  runUpdate(deps)                  编排：校验 → 下载 → sha256 → 解包 → 体检/迁移 → 备份 → install.sh
                                   由定时器与 scripts/update-now.sh 共用

src/index.ts
  update 定时器：setInterval(5 分钟) + 到点判断（仿 journal-daily）
  状态写 ~/.dsh/memory-es/update/state.json（lastCheckDate / lastResult / versions）
```

产物与日志统一放 `~/.dsh/memory-es/update/`：
`update.log`、`state.json`、`downloads/`、`prev-<version>/`（回滚证据，保留最近 2 份）。

## 5. 安全与失败处理

| 场景 | 行为 |
|---|---|
| 取不到最新版本（网络/API 失败） | 本轮跳过，写日志，明天再试 |
| 版本 ≤ 当前 | 跳过（本地版比 Release 新时不降级） |
| 取不到 `.sha256` 或校验失败 | 丢弃包、跳过 |
| 成员体检缺字段 | **不安装**，面板提示等管理员迁移 |
| 管理员迁移遇到类型变化 / 字段删除 / 团队库变更 | **不安装**，面板给差异清单 |
| 迁移请求失败 | 不安装；调一次 LLM 产出诊断文本贴面板（不执行命令） |
| `install.sh` 非 0 | 不重启，保持旧代码运行 |
| 已尝试过同一版本且失败 | 当天不再重试（`state.json` 记录），避免重启循环 |
| 重复触发 | `update.lock` 文件锁，拿不到锁直接退出 |

**防重启死循环**（关键）：安装成功但版本号没变（`install.sh` 静默失败）时，
下一轮会再次判定「有新版本」→ 又装又退出 → 无限重启。
防线：`state.json` 记 `lastAttemptVersion` + `lastAttemptDate`，同一版本当天只尝试一次。

## 6. 权限变更

**无。** 成员只读 `_mapping`（`view_index_metadata` 已有）；管理员迁移用管理员自己的身份，
不改任何角色定义。v1 里「给 `mem_personal_rw_<uid>` 加 manage」作废。

## 7. 配置与面板

`config.update`（schemastery 段）：

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 自动更新总开关（关掉后连检查也不做） |
| `at` | `'06:00'` | 每天检查时间（管理员实例部署时改成 `05:30`） |
| `timeZone` | `'Asia/Shanghai'` | 解释 `at` 的时区 |
| `repo` | `'xqh0405/dsh-memory-es'` | Release 来源 |
| `restartDelayMs` | `60000` | 安装成功到退出的延迟 |
| **`migrate`** | **`false`** | 本实例是否负责索引迁移（**只有管理员实例开 `true`**） |
| `proxy` | `''` | 仅本机直连不通时用；容器留空 |

面板：
- **设置 → 记忆库 → 配置**：`update.enabled` 渲染成开关（复用现有布尔白名单机制）。
- **设置 → 记忆库 → 维护**：新增「更新」卡片，只读展示：当前版本 / 最新版本 / 上次检查时间 /
  上次结果 / 索引是否就绪 / 是否需要人工迁移；带一个「立即检查」（只检查、不安装）。

## 8. 不做的（non-goals）

- 不做灰度/分批发布，不做签名校验（只有 sha256 + 固定仓库）。
- 不自动回滚代码；`prev-<version>/` 只是留证据，回滚靠人工。
- **成员不迁移索引**，不自动迁移团队库，不改字段类型，不 reindex。
- 不做「检查到新版本先通知再等你确认」的审批流（v1 就是自动装）。

## 9. 实施步骤

1. `src/update.ts`：纯函数（版本比较、模板提取、diff、到点判断、计划判定）+ 编排。
2. `tests/update-*.test.ts`：上述纯函数，重点是「缺字段 → wait-index」「同版本当天只试一次」。
3. `src/config.ts`：`update` 段（interface + schema）。
4. `src/index.ts`：定时器 + 状态文件 + 锁。
5. `panel/index.js` + `panel/client.js`：配置白名单、维护页「更新」卡片。
6. `scripts/update-now.sh`：手动跑一次完整链路（`--dry-run` 只打印计划）。
7. 文档：README + 《成员接入指南》第 6 节改为「插件自带自动更新」，删掉任务板方案。

## 10. 验收判据

- `npm run typecheck` 与 `npm test` 全绿。
- 纯函数测试：`0.6.54 > 0.6.9` 为真、`0.6.9 > 0.6.10` 为假；模板 diff 三类判定；缺字段 → `wait-index`。
- `scripts/update-now.sh --dry-run` 打印：当前版 / 最新版 / 索引差值 / 计划动作。
- 真机一次（dsh-test）：发一个不带字段变更的 tag，确认「下载→安装→60s 退出→拉起→版本变化」。
- 真机一次（管理员实例）：发一个加字段的 tag，确认先补 `_mapping` 再升级；成员实例该轮跳过、下一轮升级。
- 面板开关关闭后，定时器直接 return（日志可见），不产生任何网络请求。
