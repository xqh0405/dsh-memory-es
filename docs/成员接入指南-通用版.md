# dsh-memory-es 成员接入指南（通用版）

> **读者：成员本机上 DSH 的 AI 助手。**
> 成员会把「本文档 + 一份账号信息」交给你，让你在本机完成插件安装、接入共享记忆库、
> 并设置每日自动更新的定时任务。请按顺序执行本文档的每一步，**每步跑完要有证据再进下一步**。
> 拿不准的地方（比如 dsh 怎么启动的、网络不通）先问成员，不要猜着往下做。

---

## 0. 账号信息（先让成员填好这张表）

| 占位符 | 含义 | 说明 |
|---|---|---|
| `{{ES_URL}}` | 共享 ES 地址 | 例：`https://192.168.50.125:9200` |
| `{{UID}}` | 成员标识 | 同时决定 ES 账号名与个人索引后缀，**全程必须一致** |
| `{{USERNAME}}` | ES 账号 | 固定格式 `mem-user-<{{UID}}>` |
| `{{PASSWORD}}` | ES 密码 | 单独私发，不进 git、不进群聊 |
| CA 证书文件 | `ca.crt` | 管理员单独发的文件，保存到 `~/.dsh/memory-es/es/certs/ca.crt` |

**三条红线（违反任何一条都会出问题）：**

1. **不要跑发行包里的 `es/setup.sh`** —— 那是「本机自己起一套独立 ES」用的。
   我们要连的是共享库，跳过它，只做本文档的事。
2. **`{{PASSWORD}}` 不写进任何要提交到 git 的文件**；成员的 `cordis.patch.yml` 也不提交。
3. **`{{UID}}` 不要改成别人的**，它决定你读写哪些索引，对不上就是 403 或写错库。

## 1. 前置检查（逐条过，缺什么先补什么）

```bash
node -v                      # 需要 ≥ 22（dsh 本身的要求）
command -v dsh               # dsh 已安装
curl -sk --max-time 10 "{{ES_URL}}" -o /dev/null -w '%{http_code}\n'
# 期望 401（说明网络通、只是还没带账号）；超时/000 = 网络不通 → 见第 7 节
ollama list 2>/dev/null | grep bge-m3   # 需要有 bge-m3 模型
```

- **网络不通**：先确认成员机器与 `{{ES_URL}}` 在同一局域网/能路由到；共享 ES 只绑内网地址，
  不对公网暴露。不通就到此为止，联系管理员，不要改配置硬试。
- **缺 Ollama**：装 Ollama 后执行 `ollama pull bge-m3`。
  **embedding 必须是 `bge-m3`、1024 维**（与共享索引 mapping 一致）——维度写错会导致
  每次保存记忆直接 400；没装 Ollama 则只有关键词检索（降级可用，自检 05 会 FAIL）。
- **磁盘/内存**：本机不跑 ES（连共享库），只要 dsh 能跑即可，无额外要求。

## 2. 安装插件

### 2.1 拿到安装包（两种途径，任选）

**途径 A：从 GitHub Releases 下载最新版**

```bash
# 查最新版本号
curl -fsSL --max-time 30 https://api.github.com/repos/xqh0405/dsh-memory-es/releases/latest \
  | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>console.log(JSON.parse(s).tag_name))"
# 得到如 v0.6.53，代入下面两条（国内直连 GitHub 失败时，先问成员有没有代理）
VER=0.6.53   # 换成上面查到的版本号（去掉 v）
curl -fL -o dsh-memory-es-$VER.tar.gz \
  "https://github.com/xqh0405/dsh-memory-es/releases/download/v$VER/dsh-memory-es-$VER.tar.gz"
curl -fL -o dsh-memory-es-$VER.tar.gz.sha256 \
  "https://github.com/xqh0405/dsh-memory-es/releases/download/v$VER/dsh-memory-es-$VER.tar.gz.sha256"
sha256sum -c dsh-memory-es-$VER.tar.gz.sha256    # 必须 OK，不 OK 就别装
```

**途径 B：管理员直接把 tar.gz + .sha256 文件给你**（同样先 `sha256sum -c` 校验）。

### 2.2 安装

```bash
tar xzf dsh-memory-es-$VER.tar.gz
cd dsh-memory-es-$VER
./install.sh                 # 本机场景：DSH_HOME=~/.dsh，profile=web
```

- dsh 跑在容器里的成员（少数）改用：`./install.sh --dsh-home <容器内 DSH_HOME> --owner node`
- profile 不是 `web` 的用 `--profile <名字>`
- 装完会自动跑一遍七项自检；**此时 01/02/04 可能 FAIL（配置和 CA 还没做），
  属预期**，第 4 节配完再复检

## 3. 放 CA + 写插件配置

### 3.1 CA 证书

```bash
mkdir -p ~/.dsh/memory-es/es/certs
# 把管理员发的 ca.crt 放到：
#   ~/.dsh/memory-es/es/certs/ca.crt
```

放这个路径的好处：`es.caCertPath` 可以留空，插件会按固定顺序自动找到它
（`$DSH_HOME/memory-es/es/certs/ca.crt` → `$DSH_HOME/memory-es/ca.crt` → `./deploy/es/certs/ca.crt`）。

### 3.2 写配置

把下面这一段**合并**进 `~/.dsh/profiles/web/cordis.patch.yml`（与其它 `- id:` 项**同级**，
不要嵌套进别的条目里），占位符替换成账号表里的真实值：

```yaml
- id: dsh-memory-es
  config:
    es:
      url: "{{ES_URL}}"
      caCertPath: ""              # 留空=自动找上面的 CA 路径
    identity:
      userId: "{{UID}}"
      username: "{{USERNAME}}"
      password: "{{PASSWORD}}"
      teamWrite: false            # 普通成员固定 false，不要改成 true
    embedding:
      url: "http://127.0.0.1:11434"
      model: "bge-m3"
      dims: 1024                  # 必须 1024，改了会写入 400
    distill:
      enabled: false
      provider: ""
      model: ""
```

注意：

- 改 `cordis.patch.yml` 会触发配置热重载；**但本次是新装/大改，仍要走第 4 节的重启**。
- 不要动 `cordis.patch.yml` 里其它插件的条目；编辑前先备份一份
  `cp cordis.patch.yml cordis.patch.yml.bak-$(date +%s)`。
- 这个文件含密码，`chmod 600`，且不要放进任何 git 仓库。

## 4. 重启 dsh + 自检

**插件代码只在重启后生效**（运行中的进程持旧模块图）。按成员机器上 dsh 的启动方式重启：

- systemd 服务（服务名可能是 `dsh-web`）：`systemctl restart dsh-web`
- 容器里跑的：`docker restart <容器名>`
- 手动前台/后台起的：停掉原进程重新启动

重启后运行自检（在解包目录里执行）：

```bash
./selfcheck.sh
```

**七项必须全 PASS**（01 ES 连通含 CA 校验 / 02 本账号 / 03 索引齐 / 04 团队库 ACL /
05 embedding 模型与维度 / 06 插件加载清单 / 07 插件配置）。任何 FAIL 按它输出的
「下一步」修，常见归因见第 7 节。

版本核对（三处一致，都是最新版号）：
- 插件日志：`ready: v<版本>`
- 面板自检行：`[记忆库面板] 自检通过 v<版本>`
- 面板页脚：`版本 <版本>`

## 5. 验证「真的接入了共享库」

在 dsh 会话里依次做这三件事，全过才算接入完成：

1. **读自己的库**：让 AI 调 `memory_search`，随便查一个词——不报 401/403、能返回结果
   （哪怕 no_match 也行，说明鉴权与索引都在）。
2. **写一条测试记忆**：`memory_save` 存一条明显可删的测试内容，
   再 `memory_search` 能查到它；然后用 `memory_update_status`（expire）删掉这条测试。
3. **读团队库**：`memory_search` 传 `scope=team`——能读到团队共享记忆
   （普通成员只读，写团队库会 403，这是预期）。

再打开 DSH 侧边栏的「记忆库」面板，能正常打开、页脚显示版本号，即全部通过。

## 6. 自动更新（插件自带，2026-11-11 起）

不用再建任务板卡片，也不用手写 `update.sh`——插件自己每天检查、自己升级。

### 6.1 默认行为

- 每天 **06:00**（北京时间）查一次 GitHub Release；每 5 分钟醒一次判断到点没，没到点零网络请求。
- 有新版本 → **只换代码**（不碰索引：ES 是共享的，索引由管理员实例统一迁移）→ 延迟 60 秒自行退出，
  由 systemd（`Restart=always`）或容器（`unless-stopped`）拉起。
- 关闭：面板「记忆库 → 配置 → 自动更新」取消勾选（写回 profile 配置，热重载后生效）。
- 检查文件：`~/.dsh/memory-es/update/update.log`（容器里是 `/data/dsh/memory-es/update/`）。

### 6.2 索引字段变更时会发生什么

1. 管理员实例（`update.migrate = true`，建议 `at: 05:30`）先升级：比对模板字段 → 给存量索引
   `PUT _mapping` 补字段 → 校验 → 换代码。
2. 成员实例（06:00）升级前做一次**只读体检**：新版本要求的字段在自己的索引里没有 → **本轮跳过**，
   面板「维护 → 自动更新」显示「索引未就绪」，等下一轮。

所以成员不需要任何额外权限，也不会因为字段没迁上而写入 400。

### 6.3 怎么核对

```bash
node scripts/update-check.mjs   # 仓库内脚本：本地版 vs 最新 Release（只读，不安装）
```

或看面板「记忆库 → 维护 → 自动更新」：当前版本 / 最新版本 / 上次检查 / 上次结果。

### 6.4 出问题时

| 现象 | 原因 | 处理 |
|---|---|---|
| 面板显示「索引未就绪」 | 管理员还没迁移 | 等管理员升级完，下一轮自动跟上 |
| 面板显示「今天已尝试过 X」 | 安装失败过，当天不再重试 | 看 `update.log` 里的失败原因 |
| 升级后版本号没变 | 进程没重启成功 | 查 `Restart=always` / 容器 `unless-stopped`，或手动重启一次 |
| 显示「账号缺 manage 权限」 | 管理员实例没开迁移权限 | 在 ES 主机跑 `scripts/init-user.sh <uid> --team-write --with-migrate` |

## 7. 常见故障速查

| 症状 | 真因 | 处理 |
|---|---|---|
| ES 连接超时 / `ECONNREFUSED` | 与共享 ES 网络不通（不在同一内网 / 被防火墙拦） | 确认网络，联系管理员；**不要改 URL 硬试** |
| `x509` / `SELF_SIGNED_CERT_IN_CHAIN` | 缺 CA 或路径不对 | 确认 `~/.dsh/memory-es/es/certs/ca.crt` 存在且是管理员发的那份 |
| 401 | 账号或密码错 | 核对 `{{USERNAME}}`/`{{PASSWORD}}`，找管理员重置 |
| 403 | uid 与账号角色对不上，或 `teamWrite` 乱改 | 三处 uid 必须一致；`teamWrite` 固定 false；找管理员重跑 `init-user.sh` |
| 每次保存记忆 400（strict mapping） | embedding 维度不是 1024，或模型不是 bge-m3 | `ollama pull bge-m3`，`dims: 1024` |
| 面板打开是 `index_not_found` | 个人索引没建 | 找管理员在 ES 侧建 `personal_memory_<uid>` 等 4 个索引 |
| 自检 06 FAIL（装了但不加载） | `dsh.profile.bundles` 没有 `dsh-memory-es` | 重跑 `./install.sh`（它会补 bundles），再重启 |
| 改了配置/装了新版没生效 | 运行中进程持旧模块图 | **重启 dsh**；判据 = 进程启动时间晚于 `~/.dsh/local-plugins/dsh-memory-es/lib/index.js` 的 mtime |
| 更新任务下载失败 | 成员网络直连 GitHub 不通且无代理 | 配代理，或让管理员直接发最新 tar.gz 手动装 |
