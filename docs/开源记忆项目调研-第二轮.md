# 开源记忆项目调研 · 第二轮（2026-11-01）

> 第一轮（2026-10-29，[开源记忆项目调研.md](开源记忆项目调研.md)）覆盖了 Mem0/Zep/A-MEM 等 8 个框架的**写入与召回机制**。
> 本轮补三块空白：①近一年新项目（尤其已进入 DSH 生态的直接竞品）②**UI 与可视化**维度（上轮完全没有）③编码 agent / 个人会话记忆生态。
> 方法：三路并行调研（24+ 项目）+ 父代理对关键事实（claude-mem 星数、本插件排序公式、search_log 字段）实测复核。
> 星数与活跃度一律以 `api.github.com` 2026-11-01 实测为准；原始素材落盘 `.research/` 与 `scratch-research/`（gitignore，不入库）。
> 产出的优化方案已并入 [优化路线.md](优化路线.md) 阶段 9~13。

## 0. 一句话结论

**存储与检索上我们已不落后（ES 混合检索 + RRF + 排序乘子是主流同款），真正的差距在四个「之后」**：
写入**之后**的准入与隐私、召回**之后**的可解释与内容供给、检索**之后**的反馈回流、以及整个库**之后**的质量看板。
另外一个刺耳的事实：**MemOS、agentmemory、claude-mem 都已自带 DSH 插件**（claude-mem 108k⭐），生态位正在被占——
dsh-memory-es 的差异化必须押注别人没有的三样：**LAN ES 多用户团队共享（一人一索引 + ACL）、中文场景、以及「可审计 + 可解释 + 可体检」的治理面**。

## 3. 与 dsh-memory-es 的逐层差距（已核实的现状 vs 最佳实践）

现状基线（本轮实测复核）：BM25(ik)+kNN(bge-m3) 双路 RRF(k=60)；分层置信判定；排序乘子
`1 + impW×(imp-1) + moodW×affinity + hitW×log1p(hit)/10 + recencyW×exp(-age/(base×(1+强化)))`；激活扩散（默认关）；
saveMemory sha 精确去重 + 后台蒸馏（summary/keywords）+ kNN 建边；persona/traits 审核制；supersede/expire 状态机；
search_log 埋点（**记了 query/note/hits 计数/margin，但没记命中 id**）；面板三页签（概览/浏览/星图）+ 审计页。

### 3.1 写入层
| 差距 | 依据 | 现状 |
|---|---|---|
| **无准入屏障**：检索结果再摄取（反馈回路）、assistant 自述、system prompt 复述、瞬时噪音都能入库 | memoripy | memory_save 全靠 agent 自觉 |
| **无 secrets 隔离**：对话里贴了密码可以被蒸馏进库（本轮巡检就发现两起） | memoripy quarantine / deja-vu redact | 无检测 |
| **无写入来源戳** | agentmemory provenance 五通道 | 无 origin 字段 |
| **保存时无近似去重提示**（只在巡检 ingest 侧有 preflight） | agentmemory advisory similarTo | 工具链里有、产品里没有 |
| **蒸馏逐条调用，无批处理** | memobase 固定 3 次调用省 40-50% | distillRunner 逐条 |

### 3.2 召回层
| 差距 | 依据 | 现状 |
|---|---|---|
| **无检索回执**：结果不解释「哪条路命中的、贡献多少」 | memoripy receipt | 只有聚合 note/margin |
| **无分级读取**：命中后直接贴 500 字截断正文；deja-vu 实证「命中后给什么比排序更关键」 | agent-memory L0→L3 / claude-mem 三层 | 一步到位 |
| **无结果多样化**（同会话 ≤3 条） | agentmemory | 无 |
| **效用信号=检索频次**，有流行度投毒风险 | memoripy 七信号 | hit_count 只增不减 |
| **无 as-of 时间点回看** | agent-memory --as-of / Zep 四时间字段 | 字段已有（阶段 3），查询/视图没有 |

### 3.3 生命周期
| 差距 | 依据 | 现状 |
|---|---|---|
| **无人值守删除的提案制**：后台整理直接改库 | agent-memory（删除只出提案 + dream-report） | consolidate 有 pending 闸，但无统一提案面 |
| **矛盾自动 supersede 覆盖面窄** | supermemory「moved to SF supersedes live in NYC」 | 依赖极性词对规则 + 人工 |
| **无 forgetReason/失效原因留痕** | supermemory | expire 只有状态 |

### 3.4 UI

| **证据链是单向的**：记忆→来源有，记忆→「被哪些检索用过」无 | cognee Used in N answers | 审计页只到操作 |

## 4. 借鉴清单（合并去重，按价值排序）

1. **写入准入屏障 + quarantine 而非丢弃**（memoripy）——记忆质量第一道闸，防今天巡检发现的「密码进库」重演
2. **检索回执**（memoripy）——可解释、可 self-debug、直接是 UI 素材
3. **记忆质量/缺口看板**（cognee Memory Coverage 全套口径）——ES 落地只差 search_log 补命中 id
4. **双向证据链**（cognee Used in N answers + Zep Show on graph）
5. **分级读取 L0→L3 + 「命中后供给 block」**（agent-memory / claude-mem / deja-vu 实证三连）
6. **中文分词回归验证**（agent-memory 2/10→9/10→10/10 的三档方法直接照搬做基准）
7. **版本链/取代链视图 + 失效原因留痕**（reflect / supermemory 字段族）
8. **提案式删除 + dream-report**（agent-memory）——无人值守整理的伦理底线
9. **批处理蒸馏 + 固定 LLM 调用次数**（memobase）
10. **write-time provenance + 保存时近似去重 advisory**（agentmemory）
11. **写入脱敏 `[redacted:<kind>]` + secrets 盘点命令**（deja-vu）
12. **契约式回归评测 + tune**（memoripy contracts）
13. **图谱过滤语义**（来源=调暗/类型=隐藏、有界子图 truncated 诚实）+ **Canvas/LOD 性能手法**（supermemory 开源组件）
14. **thumbs 反馈落到检索轮次并回流**（cognee）
15. **「未测量≠0」呈现纪律**（cognee 全站：无数据显示「—」、进行中斜纹、刷新失败保留旧数）
16. **自描述行为协议**（mempal MEMORY_PROTOCOL / basic-memory behavior hints）——工具描述升级为行为协议
17. **规则召回通道**（SillyTavern 世界书：inclusion group、递归分层、Order/位置偏置、token 预算）——为「pinned/锚定记忆」的注入做设计参考
18. **Outdated→重建语义 + 「改配置≠清理存量」提示**（cognee + Mem0）

## 6. 差异化定位（一句话）

别人做「记忆引擎」，我们做**「可治理的团队记忆基础设施」**：
LAN ES 一人一索引 + ACL 的多人共享、中文检索、审计与体检、可解释召回、以及 10 个容器共用一个库的运维现实——
这四样 claude-mem/agentmemory/MemOS 都给不了（它们全是单机单人单 agent 模型）。
