# 情绪模块调研（2026-11-20）

> 目的：为 `dsh-memory-es` 的情绪模块（阶段 6.2~6.4）找可借鉴的做法，并判断**哪些改进有正收益、哪些不该做**。
>
> 调研方式：arXiv / 会议 PDF 全文（**精读 11 篇**，另 5 篇仅读摘要）+ GitHub API 事实核查 + Semantic Scholar 元数据。
> **第二轮（经宿主机代理 `172.19.0.1:7890` 出网）补齐了首轮被网络挡住的经典原文**：WASABI 蓝图（28 页，已精读）、Becker-Asano 主/次情绪论文（18 页）、MemEmo 情绪记忆基准、emotional-memory 的 state-of-the-art 综述。
> **每条结论标注证据强度与核实状态**，没有读到原文的一律标「未核实」。

---

## 一、结论先行

1. **我们现在的实现，覆盖面已经不低于公开项目。** 状态表示（valence/arousal）、事件合成（非模型自述）、指数衰减、阈值注入、记忆条目情绪标注、情绪一致性检索提权——这些在文献里都能找到对应物，且我们的「默认关闭 + 只提权不降权」取舍比多数项目保守。
   - 第二轮读到 WASABI 原文后可以确认：我们的 `MOOD_SILENT_THRESHOLD`（`src/mood.ts:40`）对应经典模型里的「**觉察似然 w 超阈值才被意识到**」，这是有出处的设计，不是随手拍的阈值。
2. **唯一有正面证据、且成本低的改进方向**：把「当前心情单值快照」换成「最近几条事件的情绪轨迹」。ZifaMem 的预注册实验里，多轮情绪上下文比单轮快照净偏好 **+39%**（探索性结论）；MemEmo 则指出情绪属性应是四元组 `⟨Sub, Obj, Cause, Int⟩`——我们缺的正是 **Cause**，而它恰好可以由现有 `note` 字段低成本补上。
3. **没有现成实现可以抄，连评测都得自己攒。** MemEmo 用三任务（情绪属性抽取 / 情绪记忆检索 / 情绪状态追踪更新）测了 MemOS、memobase、mem0，**没有一个系统在三个任务上都稳健**。这既是空档，也意味着任何「情绪能力提升」的说法都需要我们自己的数据来支撑。
4. **不该做的三件事**，都有直接反证据：
   - 复杂情绪状态机 —— ZifaMem 在 **5 个端点上均无可测收益**；
   - 把情绪强度加进检索打分 —— ZifaMem 的排序公式里**没有**这一项；
   - 指望情绪注入改变模型决策 —— 诱导情绪**平均不显著改变** LLM 的决策动力学。
5. **情绪模块的价值应定位在「人格连续性/表达温度」，不是「检索质量提升」。** 所有声称情绪提升检索的正面结果都是 *regime-specific*：只在「任务本身就是情绪判别」时成立（`emotional-memory` 对 LoCoMo/通用 QA 全部 FAIL）。
6. 对我们这种**编程/运维场景**（事实性检索为主），检索侧情绪加权的预期收益很低。现有 `moodWeight` 默认 0 的设定是**对的，建议保持**。

| 结论 | 来源 | 强度 | 核实 |
|---|---|---|---|
| 额外情绪状态机在 5 个端点无收益；多轮情绪上下文 > 单轮快照 +39%（探索性） | ZifaMem | A（否定）/ C（肯定） | 读全文 |
| 结构化记忆相对「完整原始历史」提升 11.4%（95% CI 6.3–17.1%），但 **ZifaMem 与 Mem0 在主要端点统计等价（±5pt）** | ZifaMem | A | 读全文 |
| 情绪加权检索的优势只在「情绪判别/情绪一致性」regime 成立；LoCoMo、DailyDialog、MADial-Bench、ES-MemEval 全部 FAIL | emotional-memory | A | 读 README（研究者自述的 claim matrix） |

| 情绪属性应是**四元组** `⟨Sub, Obj, Cause, Int⟩`，只存强度不够，要存「谁对谁的什么原因」 | MemEmo | B（设计主张，非对照实验） | 读全文 |

## 五、可落地的改进（按性价比排序）

### 5.1 值得做：注入情绪「轨迹」而非单值 [低风险]

**依据**（两条）：
- ZifaMem：「多轮 affect context > 单轮 snapshot」，净偏好 +39%（探索性，非预注册主端点）；
- MemEmo：情绪属性是**四元组** `⟨Sub, Obj, Cause, Int⟩`（主体、对象、原因、强度），只存强度不足以支撑推理。其中 **Cause（原因）** 是我们现在完全缺的。

**现状**：`renderMoodLine`（`src/mood.ts:140`）只输出一行标签 + 一句语气提示，模型看不到「为什么」。

**做法**：`MoodState.events` 已经保留了最近 20 条事件（`src/mood.ts:31,122`），`MoodEvent.note` 字段也已经在记「命中的类别」（`src/mood-events.ts` 的 `note: '明确批评'` 等）。只需把最近 2~3 条渲染出来：

```
（此刻的心情：有点闷。起因：上一轮工具报错、被指出方案有问题。语气收一点，先给结论、少开玩笑。）
```

判据：现有的 `note` 取值是「明确夸奖 / 致谢或认可 / 明确批评 / 否定或不满」这类**归类名**，本身就适合直接外露，不需要新增字段。

注意 `note` 已经刻意不含用户原文（`src/mood-events.ts` 文件头有说明），这个约束必须保持——不要为了「更具体」把对话抄进状态文档。

**验收**：现有 `tests/mood.test.ts` 加断言：平静时仍返回空串；有事件时输出包含起因短语且不含用户原文。

**进一步（不建议现在做）**：若将来要补 `Cause`/`Obj`，需要一次额外的模型调用或更细的规则，成本翻倍而收益无证据。等 5.1 落地后有观测数据再议。

### 5.2 值得做：把情绪写进记忆条目的「固化信号」[中风险，需开关]

**依据**：ZifaMem 明确说「affect 影响哪些记忆通过 promotion gate 和 strength 计算，但检索公式不该重复计这一项」。

**现状**：我们有 `valence`/`arousal` 字段（`save.ts:84-86`），但只被检索提权用到（且默认关闭）。

**做法**：让「写入时的情绪强度」参与**是否值得长期保留**的判断（例如高唤醒的批评类记忆更容易被固化），而不是参与排序。

**代价与风险**：这会改变写入行为，属于「行为变更」，按项目既有护栏应走开关 + 契约测试。**收益目前只有间接证据**（ZifaMem 的说法是设计假设，不是被单独消融验证的）。建议先只记录字段、不做决策，观察一段时间再定。

### 5.3 可选：arousal 的正交用途 [低风险，但收益不明]

**依据**：Induced Emotion Bias 引用的 DDM 框架给出 valence/arousal 的功能分离——valence 调制偏好/漂移方向，arousal 调制边界分离/处理时间（即速度–准确率权衡）。

**现状**：arousal 在 `applyMoodEvent` 里被计算（`+ |delta|×0.5`），但**注入时完全没用**（`renderMoodLine` 只看 valence）。

**判断**：这在人类被试上成立，在 LLM 上**没有对应证据**。不建议据此改行为，最多在面板里把 arousal 显示出来供观察。

### 5.4 不建议做：检索侧情绪加权默认开启

**依据**（两条，都是硬的）：
- ZifaMem 的排序公式 `0.35·sem + 0.30·strength + 0.35·importance` **没有情绪项**；
- `emotional-memory` 的预注册评测里，情绪加权的优势在通用 QA（LoCoMo）和自然对话（DailyDialog）上**全部 FAIL**，作者自己总结为「regime-specific to affect-discriminative, mood-congruent recall, not general superiority」。

**结论**：我们的场景是事实检索，落在「已证明无收益」的那一侧。`moodWeight` 保持默认 0；如果要做，必须先有自己的 A/B 证据。

### 5.5 不建议做：复杂化情绪状态机

ZifaMem 的消融直接把「additional emotion state machine」拿掉，**5 个端点都无可测差异**。我们现在的事件合成 + 衰减 + 阈值已经够用了，不要往 OCC/ALMA 那种多情绪类别、多层级、带 personality 耦合的方向扩。

### 5.6 不建议做：期望情绪注入改变模型判断

Induced Emotion Bias 的实测是：**平均而言诱导情绪不改变 LLM 的决策动力学**。也就是说，注入「你现在有点闷」更可能只是让措辞变含蓄，**不会**让模型的判断更保守或更谨慎。任何「让模型因为心情而更谨慎」的期待都没有证据支撑。

## 六、我们自己没验证、需要先验证的

调研只能告诉我们「别人怎么做」，我们自己的两个前提**从来没有被验证过**：

1. **关键词分类的准确率是多少？** `classifyUserMessage`（`src/mood-events.ts:67`）的褒/贬正则，在真实会话里的 precision/recall 没测过。文件头写「漏判比误判安全」，但没数据。**建议**：导出一批真实会话回放，人工标 100 条，算出混淆矩阵。这比任何外部论文都更有指导性。
2. **注入到底有没有被模型用上？** 我们无法直接观测。可行的间接验证：对比开/关注入时的回复文本，看「俏皮/玩笑密度」是否变化——这是可以离线统计的，不需要人类盲评。

| 方法 | 来源 | 适用 |
|---|---|---|
| **三任务分层**：① 情绪属性抽取（标签 + 四元组 `⟨Sub,Obj,Cause,Int⟩`）② 情绪记忆检索（能否召回 t−100 处触发当前情绪的「长程锚点」）③ 情绪状态追踪更新（焦虑→释然的转移轨迹、关系状态同步） | MemEmo | **最贴合我们的模块结构**：①对 `classifyUserMessage`、②对 `applyRanking`、③对 `applyMoodEvent`，一一对应 |
