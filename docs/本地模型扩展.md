# 本地模型扩展能力（默认关闭）

> 建立 2026-11-13。目标：让 dsh-memory-es 可选地利用**内网自建的 OpenAI 兼容推理网关**，
> 做检索重排、蒸馏、视觉理解这类「离线批处理」。
>
> **核心约束：全部能力默认关闭。** 不是每个人都有本地大模型 —— 没配的人必须
> **零感知、零延迟、零行为变更**。任何一项在 `enabled: false` 时都不得建立连接、不得发请求。

---

## 一、六条设计原则（改代码前先看）

1. **默认关**：所有能力 `enabled` 默认 `false`；文档里不出现「默认开」的新能力。
2. **关时零成本**：`enabled=false` 走的是「代码路径直接跳过」，不是「发了请求再丢弃」。
3. **失败必回落**：网络错误 / 超时 / 返回格式不符 → 用原有结果，**绝不把异常抛给用户**。
4. **启动不探测**：插件 `apply` 期间不连推理网关（网关关机时不能让插件启动被拖慢）。
5. **可观测**：沿用 JSONL 落盘（对齐 `recall-shadow.jsonl` 的做法），默认只记不打印。
6. **不改默认行为**：不改排序乘子默认值、不改 embedding 模型、不加 ES 字段
   （重排是查询侧的事，不碰索引）。

## 二、配置总览

一次写清，后面各阶段按需实现。

```yaml
# 共享连接块：三块能力共用一个网关，避免重复配置
localModels:
  baseUrl: ''          # 例 http://<推理网关>:8080/v1；留空 = 全部能力视为未配置
  apiKeyEnv: ''        # 凭据引用名（DSH 的 credential-ref，不读 OS 环境变量）

retrieval:
  rerank:
    enabled: false     # 默认关
    model: reranker
    candidates: 20     # 送进重排的候选数（仅在 enabled 时生效）
    timeoutMs: 600     # 硬超时；必须远小于 recall 的 3000ms 总预算
    failureThreshold: 3 # 连续失败 N 次 → 本进程内熔断
```

> 将来加 `distill.local` / `vision` 时复用 `localModels`，不各自再配一遍 baseUrl。

## 三、任务清单

### 阶段 A · 基础设施（**无行为变更**，可独立发版）

- [ ] **A1 配置项**：`src/config.ts` 增加 `localModels` 与 `retrieval.rerank`，默认全部关闭。
  - 写法对齐现有先例：`doc.autoArchive`（默认关）、`recallShadow`（注释里写清「为什么默认关」）。
- [ ] **A2 连接封装**：新增 OpenAI 兼容客户端（最小实现，只覆盖 `/rerank` 与 `/v1/chat/completions`）。
  - 连接超时与读超时分开；连接超时 ≤200ms（内网），读超时取配置值。
- [ ] **A3 可用性判定**：`baseUrl` 为空 → 该能力视为未配置，日志只记一次 `disabled`，不报错。
- [ ] **A4 熔断器**：连续失败 `failureThreshold` 次 → 本进程内禁用，记一次 warn（不每轮重试）。
- [ ] **A5 单测**：关闭时不发请求（用一个必失败的 baseUrl，断言 0 次调用）；熔断计数；超时回落。

**验收**：三闸全绿；`enabled=false` 时检索结果与改前**逐条一致**（用现有 30 条评测集）。

### 阶段 B · rerank 接入检索

- [ ] **B1 候选扩容**：仅在 `enabled=true` 时把候选数扩到 `candidates`（默认 20）；
      `enabled=false` 时**原路径一行不动**（`rrfFuse` 仍只取 `topK`）。
- [ ] **B2 插入位置**：`src/memory/search.ts` 的 `mergeScopes()` **之后**、`spreadActivation()` **之前**。
  - 理由：跨库合并后做一次请求（不是每库一次）；重排属于「相关性」，必须排在后验乘子之前。
- [ ] **B3 降级**：重排失败 / 超时 / 返回条数不符 → 用 RRF 原序，记 `outcome=fallback`。
- [ ] **B4 分数口径**：**只改顺序，不改分数**（重排模型返回 logit，不是 0–1，混进
      RRF 分数会破坏 `applyRanking` 的乘子语义）。
- [ ] **B5 文档检索是否同步**：`src/memory/doc-search.ts` 也有 `rrfFuse`；
      先只做记忆检索，文档检索单独评估（避免一次改两处）。

**验收**：`enabled=true` 时单次检索额外耗时 P50 ≤ 100ms（实测 20 条候选 81ms 热 / 154ms 首次）。

### 阶段 C · 评测与定论（**没有数字就不接**）

- [ ] **C1 关闭态回归**：`npm run eval` 与改前对比，30 条结果逐条一致。
- [ ] **C2 开启态对比**：同一评测集跑 `enabled=true`，出 recall@5 / hit@1 / MRR 对比表。
- [ ] **C3 结论落文档**：提升则记录数字并允许开；**无提升则默认关固定下来**，写清「实测无收益」。
- [ ] **C4 熔断真机验证**：把 `baseUrl` 改成不可达，连续 3 次后确认不再发请求（看计数）。

### 阶段 D · distill 改走本地（可选，前置已解除）

- [ ] **D1 配置**：`distill.local.enabled` + `model`；`enabled=false` 时仍走 `ctx.llm` 原路由。
- [ ] **D2 空正文检测**：本地模型若仍返回空 `content`（thinking 未关），
      **判失败并回落云端**，而不是把空串当成蒸馏结果写库。
  - 前置已解决：推理网关侧对 Qwen3 系模型加了 `--chat-template-kwargs '{"enable_thinking":false}'`，
    实测 `content` 正常、无 `reasoning` 字段。
- [ ] **D3 JSON 稳定性**：蒸馏要结构化输出，用真实记忆跑 20~30 条，统计解析失败率；失败率 >5% 不接。
- [ ] **D4 回退开关**：一条配置即可切回云端（`provider/model` 不变，只切 `local.enabled`）。

### 阶段 E · 视觉理解（可选，绕道用）

- [ ] **E1 调用形态**：只做「脚本 / 子代理调网关」，**不接入 agent 主上下文**
      （主对话模型不是本地网关，模型进不了上下文）。
- [ ] **E2 用途限定**：截图/图表理解、报错截图转文字；产出以文字结论回传。

### 阶段 F · 可观测与面板

- [ ] **F1 JSONL 记账**：`{on, ms, candidates, changedTop1, outcome}` 落盘，默认不打印。
- [ ] **F2 维护页展示**（可选）：`/maintenance` 加一行「本地模型：关 / 开 / 已熔断」。
  - 注意：面板 API 统一包 `{ok, value}`，新字段要同步 `TAB_ORDER` 之类的白名单。

## 五、明确不做

1. **不换 embedding 模型**。网关上的 `qwen3-embedding` 虽然也是 1024 维，但与 bge-m3
   **不是同一个向量空间**，混用必错；要换只能整体重建全库向量，与「不换向量模型」的定调冲突。
2. **不把本地模型当 agent 主对话模型**。实测 120B 稳态 3.8~52 t/s（含加载），
   且 agent 固定开销约 6.9 万~19.8 万 tokens，上下文与延迟都不合适。
3. **不新增 ES 字段 / 不改索引模板**：重排是查询侧能力。
4. **不改排序乘子默认值**（`applyRanking` 的系数保持原值）。
