# 本地模型扩展能力（默认关闭）

> 建立 2026-11-13。目标：让 dsh-memory-es 可选地利用**内网自建的 OpenAI 兼容推理网关**，
> 做检索重排、蒸馏、视觉理解这类「离线批处理」。
>
> **核心约束：全部能力默认关闭。** 不是每个人都有本地大模型 —— 没配的人必须
> **零感知、零延迟、零行为变更**。任何一项在 `enabled: false` 时都不得建立连接、不得发请求。

---

## 一、六条设计原则（改代码前先看）

1. **默认关**：所有能力 `enabled` 默认 `false`；文档里不出现「默认开」的新能力。
2. **关时零成本**：`enabled=false` 走的是「代码路径直接跳过」，不是「发了请求再丢弃」。
3. **失败必回落**：网络错误 / 超时 / 返回格式不符 → 用原有结果，**绝不把异常抛给用户**。
4. **启动不探测**：插件 `apply` 期间不连推理网关（网关关机时不能让插件启动被拖慢）。
5. **可观测**：沿用 JSONL 落盘（对齐 `recall-shadow.jsonl` 的做法），默认只记不打印。
6. **不改默认行为**：不改排序乘子默认值、不改 embedding 模型、不加 ES 字段
   （重排是查询侧的事，不碰索引）。

## 二、配置总览

一次写清，后面各阶段按需实现。

```yaml
# 共享连接块：三块能力共用一个网关，避免重复配置
localModels:
  baseUrl: ''          # 例 http://<推理网关>:8080/v1；留空 = 全部能力视为未配置
  apiKeyEnv: ''        # 凭据引用名（DSH 的 credential-ref，不读 OS 环境变量）

retrieval:
  rerank:
    enabled: false     # 默认关
    model: reranker
    candidates: 20     # 送进重排的候选数（仅在 enabled 时生效）
    timeoutMs: 600     # 硬超时；必须远小于 recall 的 3000ms 总预算
    failureThreshold: 3 # 连续失败 N 次 → 本进程内熔断
```

> 将来加 `distill.local` / `vision` 时复用 `localModels`，不各自再配一遍 baseUrl。

## 五、明确不做

1. **不换 embedding 模型**。网关上的 `qwen3-embedding` 虽然也是 1024 维，但与 bge-m3
   **不是同一个向量空间**，混用必错；要换只能整体重建全库向量，与「不换向量模型」的定调冲突。
2. **不把本地模型当 agent 主对话模型**。实测 120B 稳态 3.8~52 t/s（含加载），
   且 agent 固定开销约 6.9 万~19.8 万 tokens，上下文与延迟都不合适。
3. **不新增 ES 字段 / 不改索引模板**：重排是查询侧能力。
4. **不改排序乘子默认值**（`applyRanking` 的系数保持原值）。

## 八、实测结果（2026-11-13，本机 114 → 127 llama-swap）

### 8.1 阶段 C：重排的开启态对比（30 条评测集，gate=off）

关闭态 = 产出本表的同一份代码、不启用重排；开启态 = `--rerank --gateway http://192.168.50.127:8080/v1`。

| 组 | hit@1 | hit@5 | MRR | 重排 P50 |
|---|---|---|---|---|
| **关闭态（基线）** | | | | |
| single | 88% | 100% | 0.938 | — |
| paraphrase | 13% | 88% | 0.500 | — |
| exact | 38% | 88% | 0.625 | — |
| **开启：candidates=20, docChars=600（默认）** | | | | |
| single | 75% | 100% | 0.854 | 423ms |
| paraphrase | 25% | 88% | 0.542 | |
| exact | 25% | 88% | 0.542 | |
| **开启：candidates=10, docChars=300（最优组）** | | | | |
| single | 75% | 100% | 0.875 | **128ms** |
| paraphrase | 25% | 100% | 0.542 | |
| exact | 38% | 100% | 0.667 | |
| **开启：candidates=10, docChars=600** | | | | |
| single | 75% | 100% | 0.854 | 214ms |
| paraphrase | 25% | 88% | 0.542 | |
| exact | 25% | 88% | 0.563 | |

**结论：实测无显著收益，`retrieval.rerank.enabled` 保持默认 `false`。**

三点依据：
1. 综合 MRR：关闭 0.688 → 最优组 0.695（+1%，30 条样本内属噪声）；
   默认参数组反而是 0.646（-6%）；
2. 结构性的坏消息：**single 的 hit@1 从 88% 掉到 75%**——重排把原本第一的正确条目挪走了，
   paraphrase 的 hit@1 上升（13%→25%）抵不过这个损失；
3. 延迟：最优组 P50 128ms，仍超本任务验收线（≤100ms）；默认参数 423ms。
   真实记忆的正文比短文档长得多，`600 字 × 20 条` 的重排计算就是这个量级。

抽样定位（q24）：重排给期望条目 0.344 分排第 9，而给「构建/发布实操」的同类条目 4.8~5.3 分排前二。
不是「接口接错」，是重排模型与人工标注口径不一致——这也解释了 single 掉、para 升的形态。

### 8.2 阶段 C4：熔断真机验证

`docChars=1000` + 20 条候选那组超出 600ms 总超时 → 连败 3 次后
日志出现 `rerank_tripped`，之后每条都记 `outcome=tripped`（记账 n=30、P50=0ms），
检索结果自动退回 RRF 原序（数字与关闭态一致）。

### 8.3 阶段 D：本地蒸馏（30 条真实 active 记忆）

| 模型 | 解析成功 | 失败率 | P50 / P95 | 备注 |
|---|---|---|---|---|
| **qwen3-4b（默认）** | 30/30 | **0%** | 4.8s / 11.1s | aux 常驻，不参与 big 组互斥 |
| qwen3-30b | 29/30 | 3.3% | 3.6s / 9.0s | 会占用 big 组；失败样本是未闭合 JSON |

失败率判据 ≤5%，两者都过。**选 4b 的理由不是准确率，而是它不会把用户正在用的大模型踢掉。**

### 8.4 阶段 E：视觉

`qwen3-vl-8b`，`data:image/png;base64,…` → **926ms**，对表情包描述准确。
调用形态只走脚本/子代理，没有接进 agent 主上下文。

## 九、实现偏离记录（与原设计的差异 + 原因）

1. **B4 的「只改顺序不改分数」改为「在候选自身分数区间内按名次重排」。**
   `spreadActivation` 与 `applyRanking` 都按 `fusedScore` 重排（乘子默认非 0），纯顺序会被抹平。
   试过两种替换：写死 `1/(k+rank)` → 参与候选与**未参与候选**不可比，30 条几乎全部 ✓→✗；
   区间内插值后顺序与尺度都稳定。**不混 logit** 这条底线没破。
2. **A2 的「连接超时 ≤200ms」取消，改成单一总超时。**
   llama-server 的 `/rerank` 不是流式：响应头要等服务端算完才发，
   「headers 未到」既可能是建连失败，也可能是模型在算（真实记忆 250~400ms）。
   200ms 卡 headers 实测 3/3 误杀 → 熔断。代价是连不上时最多等满 `timeoutMs`，由熔断兜住。
3. **D1 默认模型 30b → 4b。** 见 8.3：4b 是 aux 常驻、不抢 big 组、解析失败率更低。
4. **新增 `retrieval.rerank.docChars`（默认 300）。** 原设计没有这个旋钮，但它同时决定
   准确率与延迟（600 字 × 20 条 = 423ms），必须能调。

## 十、怎么开（给后来的人）

```yaml
dsh-memory-es:
  localModels:
    baseUrl: http://192.168.50.127:8080/v1
    apiKeyEnv: LLAMA_SWAP_KEY        # $DSH_HOME/.credentials.yaml 里的 ref 名
  retrieval:
    rerank:
      enabled: false                 # 实测无收益，保持关（见 8.1）
      candidates: 10
      docChars: 300
  distill:
    local:
      enabled: true                  # 推荐开：4b 常驻、0% 解析失败、不抢大模型
      model: qwen3-4b
```

- 只开 `distill.local` 时，检索路径**完全不变**（rerank 的 enabled 仍是 false）。
- 关掉 `localModels.baseUrl` = 全部本地能力视为未配置，零请求。
- 面板 `/maintenance` 已返回 `localModels` 字段（配置态 + JSONL 末条），前端那一行还没做。
